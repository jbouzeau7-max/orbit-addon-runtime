# Pistes d’évolution

Ces idées ne font pas partie de la version actuelle ; elles ne sont pas présentées comme disponibles.

1. Adaptateurs de persistance injectables avec migrations versionnées par extension.
2. Schéma JSON publié et compatibilité de versions de l’API hôte.
3. Tests de plugins en processus séparé avec IPC à capacité minimale.
4. Signature et vérification de paquets, catalogue opt-in, politique de révocation.
5. Adaptateurs d’interface multiplateforme pour thèmes, polices et jeux d’icônes.
6. Outils de diagnostic des dépendances, conflits de versions et temps de démarrage.

Tout adaptateur d’exécution de code tiers devra définir une véritable frontière de sécurité avant l’ajout d’un catalogue communautaire.
